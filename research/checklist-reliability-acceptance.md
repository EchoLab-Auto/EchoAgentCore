# Checklist 可靠性整改验收计划

## 范围与约束

- 所有权保留在 `agent-module-tools`，不迁仓，不改线上配置、清单或历史数据，不部署、不重启。
- 工具是入口，模块级 Store 是真值；人格重建共享同一 Store，重启从模块独立数据文件恢复。
- 清理历史/归档历史默认保留任务清单。会话清单重置由明确的 `reset_session` 操作完成；不假称历史和清单已经原子重置。
- 固定验收矩阵是验收标准；实际执行结果见文末「验证记录」。

## 固定验收矩阵

| 类别 | 场景 | 必须满足 |
| --- | --- | --- |
| 安全 | 条目/名称含已登记的假秘密，引号与换行 | 返回文本、状态快照、持久文件及模型摘要无明文；JSON 字段类型不变 |
| 安全 | 注册表快照出口读锁竞争 | 不因竞争绕过脱敏 |
| 安全 | 文件损坏、版本未知、过大或读取失败 | 明确错误，不空状态覆盖原文件 |
| 状态 | 查不存在的会话/清单，错误索引/操作/批量输入 | 只读或失败前后状态及版本均不变 |
| 状态 | 创建空清单，删除最后一项或重置 | 空清单可发现；权威空快照能清掉前端旧投影 |
| 恢复 | 人格重建，同路径重新打开 Store | 状态、稳定 ID、修订号正确恢复 |
| 并发 | 两个写请求携带同一个预期版本 | 至多一个成功，另一个冲突可见，不静默覆盖 |
| 身份 | 删除/重排后持旧 ID 或旧位置编号修改 | 不误改其他条目 |
| 重试 | 同 request_id 同请求 / 不同请求 | 同请求不重复添加；不同请求明确冲突 |
| 持久化 | 临时文件/写盘/rename 失败 | 不返回普通成功，不发布未持久的新状态 |
| 取消 | 调用 future 在写入阶段被取消 | 内部提交任务继续一致地结束，不出现磁盘新、内存旧 |
| 生命周期 | 清历史、归档历史、重置清单 | 前两者保留清单；reset_session 变更状态代次，旧请求不复活 |
| 同步 | F5、断线重连、切区域再切回、Core 重建 | 可补拉权威快照，旧缓存不能被当成新状态 |
| 同步 | 旧版本事件晚于新版本到达 | 不允许旧事件回滚新投影 |
| 作用域 | 同名人格跨 Core；同名清单跨会话 | 权限不串用、状态不覆盖、聚合卡 key 唯一并标注来源 |
| 门控 | 工具关闭，但此前存在清单 | 不删除数据；允许只读观察，不向模型注入必须调用不可用工具的要求 |
| 模型 | 上下文压缩后、遗忘清单名称 | list 可枚举；有限额摘要提供活动计划；get 可恢复完整状态 |
| 容量 | 会话/清单/条目/文本/文件超过上限 | 失败明确，无部分修改；摘要有固定上限 |

## 分组与回退

1. 注册表结构化快照脱敏、失败无副作用、空清单可见。
2. Store、稳定 ID、事务写入、版本/幂等、持久化故障测试。
3. Core 查询/全量快照及 Panel 作用域和重同步。
4. 模型短摘要、技能、文档、整体验证与独立复核。

每组独立审查；测试日志放 `/tmp`，产物不安装。协议生成文件按 Core 类型生成，不手抄。
上线另行安排：现有内存清单在任何重启前须导出/迁移，不在本次开发中清空。持久格式变更需备份；损坏文件只报错不自修。

## 独立复核与剩余边界

- Core 独立复核未发现数据丢失、泄密、错状态或协议破坏类阻断项。
- Panel 独立复核发现的多 Core 独立重连/删除残留、full 后旧 live 复活及重连乱序问题均已修复并加入回归；聚焦复核确认版本重定基与旧 full/live 防护有效。
- 跨 Store / 跨进程保护针对遵守 `.save-lock` 与文件指纹协议的协作写者；不遵守协议的外部写者无法由本模块阻止。
- 陈旧 Store 会拒绝覆盖新文件；当前运行时没有热 reload 命令，需重新打开 Store（现有部署中为重启 Core）后再恢复该实例写入。
- 本次以 Store 重开和真实子进程测试验证恢复/并发，不实际重启线上 Core。
