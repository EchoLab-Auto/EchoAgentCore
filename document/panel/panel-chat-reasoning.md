# 推理块与活动浮条

> **定位**：工作行 reasoning 项的正文层（`ReasoningText`）与输入区上方的活动浮条——实时与历史两种呈现、默认折叠与推演滚动跟随、落位与可见性判据。读者：维护 `ReasoningText.vue` / `WorkRunGroup.vue` 的开发者。上游：[工作行](./panel-chat-work.md)；去重与水位线见[历史与实时窗口](./panel-chat-history.md)。

## 推理块的呈现

- **实时（流式）**：内容随增量实时生长（全量跟随、不播打字机），自动展开 + 钉底 + 「实时输出…」提示 + 光标；流结束（终值对账）回到默认折叠态
- **实时（整段，stream_output 关闭/非流式路径）**：打字机逐字——24ms/tick，每 tick ≥2 字符，总时长约 6s 封顶（按文本长度自适应提速）；chip 紫色呼吸（`work-run-pulse-reasoning`）+ 星形图标闪烁（`work-think-pulse`），展开的详情头显示「正在推演…」+ 闪烁光标
- **历史**：一次性全量显示，无动画
- 动画纯视觉层（`animate` 元数据不参与逻辑）

## 折叠与滚动跟随

- **折叠（默认折叠）**：静止态是一枚 30×26 的紫色 chip（星形图标），点击展开正文卡（`ReasoningText`）；再点或点其他 chip 收起，一次只展开一项。chip 没有 `aria-expanded`——无障碍名固定为 `aria-label="思考"`，状态全在 `title` 悬停提示里（`思考 · 正在推演…` / `思考 · 1.2k 字`）
- **字数徽标**：**播放中**chip 右下角显示紧凑字数（`1.2k`，随 50ms ticker 刷新）；静止后徽标消失，完整字数（`1.2k 字`）改在详情头显示
- **自动开合**：推演中（打字机进行 / 真流式未结束）自动展开、播完自动收起；用户手动点过的条目进入「手动优先」，此后自动开合不再覆盖它（`WorkRunGroup` 的 `userToggled`）
- **推演滚动跟随**：思考框体为**限高滚动窗口**（max-height 180px），打字机每次推进后（`flush: 'post'`）滚动钉底（`scrollTop = scrollHeight`）——推演中始终可见最后一行，不撑爆时间线；推演结束后手动展开时滚动复位到顶部（从头阅读）

## 落位与可见性

- **落位**：推理条目按 `state.trunk` 的到达顺序插进时序——思考夹在前后两次工具调用之间，不堆到主回复后面；历史快照与实时窗口合并时同样按这个顺序落位（见[历史与实时窗口](./panel-chat-history.md)）
- **可见性与去重**：推理**永不**按 seq 水位线过滤；实时孪生被权威条目认领时保留 `seq = 0`（见[历史与实时窗口](./panel-chat-history.md)）。去重只走内容判据：剥掉线上截断标记后比前缀——推理在线上会被 `elide_reasoning_for_wire` 截断，全文与截断文本永远无法「完全相等」，按 strict 判等会把同一条思考判成两条

## 活动浮条

输入区上方的胶囊浮条（仅当前会话忙碌时可见）：旋转 spinner（0.8s）+ 相位文案（`ChatView.vue` 的 `activityText`）——`正在思考：{detail}…`（无 detail 时「正在思考…」）/ `正在调用工具 {detail}…`（该工具对当前 persona 不可见时降级为「正在处理…」）/ `子代理工作中：{detail}…`（无 detail 时「子代理工作中…」），320px 省略截断。
