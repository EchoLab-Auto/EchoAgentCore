# 设置 · Core 与联邦

> **定位**：「Core 连接」分类的完整交互——接入点管理（直连 / SSH 隧道）与**同页下半区的联邦网络**（组建向导、拓扑视图、手动配对通道）。菜单与切换语义见[设置视图](./settings.md)。读者：维护连接管理与联邦界面的开发者；相关：[Panel 前端](./panel.md)「配置与运维」（中继、访问令牌、分布式调度）、[联邦（多机）](../federation/federation.md)（架构、占位提升、配对无方向性与安全模型）。

联邦**不是独立分类**，是本页内的下半区：上半区是接入点管理，下半区是 Core 之间的联邦网络。

## 接入点管理

在设置页在线增删接入点（写回 `[[cores]]` 段持久化，中继动态并入 / 摘除、无需重启）；单接入点兜底（`[core]` 或一条 `[[cores]]`）与访问令牌、分布式调度见[Panel 前端](./panel.md)「配置与运维」。

**接入方式**：直连 ｜ **SSH 隧道**——云服务器只开 SSH 端口时选后者。

**列表是紧凑网格**（2026-10 布局改）：`repeat(auto-fill, minmax(min(100%, 340px), 1fr))`——宽屏 2-3 列、窄屏自动退化为单列（不需要媒体查询）。每个接入点一格、**两行**：第一行状态点 · 名称 · 来源标签（`SSH` / `自动`）· 编辑 / 删除；第二行地址 · 连通性 · 认证徽标，地址是第一让位者（省略 + 悬停给全量）。`last_error` 只在真有错误时多占一行（不做 `visibility` 占位——那会让卡片高度在有无错误之间跳）。改动前每张卡片独占一整行且内含 32px 固定「健康」占位（≈100px/格，5 个接入点占 500px+），现在 5 个在 1440px 宽下 3 列 2 行共 ~160px。

### 刷新与「不闪」约定（2026-10）

接入点状态**不轮询**在组件里：`main.ts` 的全局泵（`startUpstreamsPolling`，8s、后台标签页暂停）是唯一数据源，`state.upstreams` 由它维护；设置页只读。两条铁律：

1. **结构没变的刷新不产生 DOM 变更**——`refreshUpstreams()` 在内容与上一帧相同（`JSON.stringify` 比较）时不写 `state`；加载指示只出现在用户主动触发的动作上（首屏文案 / 「刷新」按钮自身的 loading）。历史上每次 `refresh()` 都把 `loading` 翻真、模板据此往列表插一块 spinner 再摘掉，实测 5 张卡片每 3s 上下跳 46px，观感就是「Core 连接页一直在闪」。
2. **并发请求共享同一 promise**（`inflight` 去重）——避免页面内的即时刷新与全局泵撞车，同一次快照被拉两遍、被赋值两遍。

## SSH 隧道

表单含 SSH 主机 / 端口（默认 22）/ 用户（须为运行 Core 的用户）/ 私钥文件（可空 → ssh-agent / 默认密钥）/ 口令或密码（可选，编辑留空 = 不变）/ 远端 management 端口（默认 3132）/ 远端媒体目录（可空 = 默认）。

Panel 后端以 russh 直连 SSH 并把远端 management 端口**本地端口转发**给中继（隧道指数退避自动重连、本地端口稳定；主机密钥 known_hosts 校验 + 首连 TOFU，`accept_new_host_key=false` 关闭）。列表行展示 `ssh://user@host → :远端端口`、SSH 徽标与隧道阶段（连接中 / 已连接 / 离线 + 失败原因）。编辑既有 SSH 上下游时密文留空 = 保留旧值（与访问令牌同语义）。

## 联邦组建向导

「创建联邦 / 添加节点」按钮随拓扑状态切换文案，点击打开向导：

- 勾选要纳入的节点（默认全选**在线**的已接入 Core；离线节点禁选），显示「已互联 X 对 / 将新建 Y 对」（全互联补全）
- 执行时逐对完成「一侧生成邀请 → 另一侧登记接入 → 等链路在线」；默认方向失败**自动换向重试一次**，两方向均失败则清理已登记条目并标记失败（可「重试失败项」）
- 已配置的对自动跳过（含离线链路——重连是链路自身行为，无需重新配对）

## 拓扑视图

无向导时的上半区：节点间链路一览（`a ── b`，在线绿色加粗），数量摘要「N 个节点 · M/K 条链路已配置 · X 条在线」。互联判定：链路在线时按 Core 回传的对端 `node_id` 精确匹配；离线 / 旧 Core 缺失时按 peer 名兜底（Panel 配置名 / node_name / `node-<id 前 8>`）。

## 手动配对通道

每个 Core 卡片内保留：生成邀请串（一次性 token，含共享密钥按密钥级保密）、添加 / 编辑 peer（粘贴 `echofed://` 邀请串自动解析）、逐项收紧授权（工具 / 查询 / 委派 / 需确认）；编辑回填现有授权，不以默认覆盖。
