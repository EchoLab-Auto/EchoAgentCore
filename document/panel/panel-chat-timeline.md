# 主时间线时序与动画

> **定位**：主时间线对 Agent 运行过程的展示规范——三条一致性基线（及时性、时序表现、动画反馈）与动画的作用边界，改动时间线渲染时的对照清单。读者：维护 `state.ts` 事件投影与 `ChatView` 渲染的开发者。上游：[会话消息区](./panel-chat-messages.md)；落位判据见[历史与实时窗口](./panel-chat-history.md)，工作行的呈现见[工作行](./panel-chat-work.md)。

主时间线对 Agent 运行过程的展示规范（一致性基线，改动需保持三条规则）：

## 及时性（实时渲染，不缓冲）

`AgentReasoning` / `ToolCall` / `ToolResult` / `AgentOutput` 事件到达即渲染进主时间线，**不得**等回复完成后一次性写入；推理是独立 `reasoning` 角色消息按序插入，不缓冲到回复尾部。**真流式**：模型增量经 `AgentContentDelta` / `AgentReasoningDelta` 逐段到达（~40ms 合并批），逐段实时生长；终值 `AgentOutput` / `AgentReasoning`（全量）到达时**对账替换**流式行内容（丢帧/乱序自愈，展示以终值为准）。分步切分：`ToolCall` 到达 = 该步为中间叙述（冻结当前行保留文本）；下一步增量新建一行，终值只替换最新流式行。取消/错误冻结流式行（保留已显示部分）。

## 时序表现（还原真实顺序）

主时间线顺序 = 事件到达顺序（`用户消息 → 推理 → 工具调用 → 工具结果 → … → 正式回答`），推理真实穿插在工具调用之间，正式回答始终最后；**这个顺序由数据层保证**——快照与实时窗口合并时按实时到达顺序插进时序，而不是把「快照里没匹配到」的条目追加到末尾（判据见[历史与实时窗口](./panel-chat-history.md)）。历史回放（`loadTimeline`）同样把 `backend.reasoning` 拆分为独立 reasoning 消息、插在回答之前，与实时路径时序一致；侧边栏临时分支详情继承同一规则（仅做连续 reasoning 的合并展示）。

## 动画反馈（对应位置对应动画）

| 阶段 | 位置 | 动画 |
| --- | --- | --- |
| 连接中 | 边栏「连接状态」卡（由原顶栏状态点迁入，可拖到任一列） | 状态点呼吸 + 重连提示 |
| 思考 / 调用工具 / 子代理 | 输入区内状态行（文本域下方） | 会话生效 API 徽标 + 旋转 spinner + 动态文案 |
| 推理输出（流式） | 思考 chip + 详情卡 | 内容随增量实时生长（自动展开 + 钉底 + 「实时输出…」提示 + 光标）+ chip 紫色呼吸 |
| 推理输出（整段） | 思考 chip + 详情卡 | 打字机逐字显示（自适应速度，约 6s 封顶）+ 光标 + chip 紫色呼吸与星形图标闪烁 |
| 工具执行中 | 工具 chip | 呼吸脉冲（`work-run-pulse`，仅工具 chip）+ 该工具图标的专属 SVG 动画 + 右下角实时耗时角标（**无 spinner**） |
| 子代理执行中 | 子代理 chip | 青色呼吸（`work-run-pulse-subagent`）+ 图标闪烁 + 右上角青色转圈点 |
| 消息到达 | 每条实时消息 | 0.28s 淡入上移入场动画 |

## 动画边界

- 打字机/入场动画**仅**对实时消息（`DisplayMessage.animate === true`）播放；历史回放、刷新加载不播动画
- 动画为纯视觉层：`animate` 是展示元数据，不进入任何数据/逻辑判断
- 实现要点：ui-frame `ChatRole` 不含 `reasoning`，必须在 `ChatView` 的消息行渲染层拦截（自渲染行循环；否则未知角色会被渲染成 Agent 气泡）；`pendingReasoning`/`completedReasoning` **已删除**（2026-10 巡检确认是死状态：分支合并块随 ui-frame 移除后无任何读取方，仅剩声明与初始化，已连同声明一并清掉，`state.ts` 只留一行说明）
