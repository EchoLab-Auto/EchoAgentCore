# 联邦·管理端口合并（规划）

> **定位**：本页是「单端口合并」的设计记录——让管理 WS（Panel 通道）与联邦链路共用一个监听端口，一条 NAT/防火墙映射同时服务面板与联邦。读者：联邦与部署功能的维护者、多机用户。**状态：已实施（2026-10）**——运行行为见 [联邦（多机去中心化）](./federation.md) 的「端口合并」子节与 [协议与数据流](./protocol.md)；本页保留设计与决策记录。
> 相关：[联邦（多机去中心化）](./federation.md)（链路与认证现状）、[部署与自更新](./ops-deploy.md)（端口与映射）。

## 动机

NAT 后的节点（云机、容器预览环境）要同时提供两个对外面：面板连**管理
WS**（缺省 :3132）、对等节点连**联邦**（缺省 :3133）——意味着两条独立
的端口映射，每加一台机器都要维护两倍映射，排查时还要区分「连错端口」
与「令牌不对」（两者症状在历史上高度相似）。

合并后：**一个端口、一条映射**，面板与联邦共用；对端（含旧版本）对
合并完全无感（见「兼容性」）。

**非目标**：不合并 QQ 端口（OneBot 反向 WS，不同协议族）；不改变默认
端口布局（默认仍 3132/3133 独立，合并是显式配置动作）。

## 现状与关键观察

| 通道 | 监听（缺省） | 升级认证 | 令牌命名空间 |
|---|---|---|---|
| 管理 WS | `0.0.0.0:3132` | `Authorization: Bearer <management_access_token>`（空 = 不校验，回环信任模型） | 单令牌，全权 |
| 联邦 | `0.0.0.0:3133` | `Authorization: Bearer <per-peer token>`（必须匹配某已知 peer） | 每对等节点一条，权限受 per-peer 策略收敛 |

两条链路的连入侧**在 wire 层完全同构**：都是 WS 升级 + Bearer 头认证，
差别只在**令牌命名空间**与升级后的帧协议。

> **关键观察**：两个令牌命名空间互不相交且都有显式来源——**令牌本身
> 就是天然的路由键**。合并监听端在升级回调里按令牌分流即可，线协议、
> 帧格式、invite 串、dial 侧、面板侧全部零改动。

## 设计

### 单端口分类路由

合并条件：`[core] management_address` 与 `[federation] listen` 为**同一
地址**（trim 后字符串相等，均非空）→ 只起一个监听；否则维持现状各起
各的。

```text
                  ┌─ Bearer == 管理令牌 ─────→ 管理 WS（BackendBridge / Agent）
 合并端口 :3132 ──┼─ Bearer ∈ peer 令牌表 ───→ 联邦链路（Hello/Welcome → run_link）
 （单监听）       └─ 其余 ──────────────────→ HTTP 401（统一拒绝）
```

分类决策表（升级回调内同步判定；「管理令牌」= `management_access_token`）：

| # | 呈现的 Bearer | 管理令牌 | 归为 | 说明 |
|---|---|---|---|---|
| 1 | = 管理令牌 | 非空 | 管理 | |
| 2 | = 某 peer 令牌 | 任意 | 联邦 | 前提：两表无相等项（启动/运行时校验拦下） |
| 3 | 其他非空 | 非空 | 401 | 未知令牌，标准 401 |
| 4 | 其他非空 | 空 | 管理 | 兼容旧行为（旧监听不校验未知令牌）；仅回环可达（见安全条件） |
| 5 | 无 / 空 | 空 | 管理 | 兼容旧行为 |
| 6 | 无 / 空 | 非空 | 401 | |

判定顺序按上表自上而下；表 1 与表 2 的「相等冲突」（管理令牌 == 某
peer 令牌）被启动校验挡下，因此顺序无歧义。

升级完成后按角色分派：

- **管理** → 既有连接主体（事件广播 + 命令泵），行为与现监听完全一致；
- **联邦** → `Federation::accept_ws(ws, presented_token)`——即现有
  `accept_one` 去掉认证段后的部分（Hello/Welcome → `run_link`），
  `presented_token` 用于反查 peer 配置名。

401 复用标准 401 拒绝（非静默断开）——此前修复的「令牌问题伪装成协议
故障」语义在合并模式下同样成立，排查体验一致。

### 配置面（缺省合并，2026-10 定稿）

无新增配置键：**`[federation].listen` 未配置 = 缺省合并**（联邦跟随
管理地址；用户实际反馈「联邦不该再是独立端口」后由「显式同址」演进而
来）。三个保守场景自动回退独立监听 `0.0.0.0:3133`（启动警告注明原因）：
① 管理地址回环（合并会把联邦拉进回环、外部 peer 不可达）；② 管理令牌
为空且非回环；③ 管理令牌与某 peer 令牌相同（升级回调无法区分两类
连接）。显式配置保留逃生舱口：

```toml
# 例 1：典型零配置（NAT 云机）——联邦自动并入管理端口，一条映射通吃
[core]
management_address = "0.0.0.0:3132"
management_access_token = "<token>"
# [federation] 不写 listen → 缺省合并（federation 显示 [缺省·合并]）

# 例 2：显式独立监听（逃逸舱口）
[federation]
listen = "0.0.0.0:3133"

# 例 3：显式同址（与缺省合并等效；fail-closed 校验照常）
[federation]
listen = "0.0.0.0:3132"
```

- `[federation] listen = ""`（纯连出）不参与合并；
- `echo-agent-core port` 输出合并标记（`[缺省·合并]` / `[配置·合并]`）与
  回退注脚（含原因）；显示与运行期共用 `plan_federation_listen` 规划函数，
  零口径差。

### 安全条件

合并把「面板通道」暴露在「联邦端口」上——这是**新增的风险面**：**显式**
合并配置用 fail-closed 把关（拒绝启动）；**缺省**合并（自动生效）在危险
组合下保守回退独立监听（不拒绝启动、附启动警告）：

1. **显式合并 + 管理令牌为空 + 绑定非回环 → 拒绝启动**。错误信息含补救
   命令（`echo-agent-core token --rotate` 后重启）。缺省合并遇到该组合
   自动回退独立监听（不拒绝启动）。
2. **显式合并 + 管理令牌与任一 peer 令牌相等 → 拒绝启动**；运行时
   `SaveFederationPeer` 引入冲突令牌同样拒绝（邀请串随机令牌冲突概率
   可忽略，不额外处理）。缺省合并遇到该组合自动回退独立监听。
3. 令牌比较统一常时比较（管理侧已是；联邦侧顺手对齐）。
4. 威胁模型不变：管理令牌 = 全权；peer 令牌 = 该 peer 的策略收敛面。
   合并端口应视同敏感端口，文档与启动日志明确标注。

## 兼容性

分类路由不改变任何线格式，**对端无需同步升级、无需改配置**：

| 对端 ↓ \ 本端 → | 旧版本（独立 :3133） | 新版本·独立模式 | 新版本·合并模式（含缺省） |
|---|---|---|---|
| 旧面板 | ✓ | ✓ | ✓（管理令牌/无令牌路由至管理） |
| 旧联邦 dial 入 | ✓ | ✓ | ✓（peer 令牌路由至联邦） |

**升级注意（缺省合并的监听位置变化）**：升级到本版本后，未显式配置
`[federation].listen` 的节点，联邦监听从 `0.0.0.0:3133` 变为**管理端口**
（缺省合并；管理地址回环等保守场景除外）。对端配置里指向旧 3133 地址的
`peer.url` 需更新为对方的新联邦地址（= 对方管理端口及其对外映射）；
或留空 `url`（仅接受连入）依赖对端拨入——链路建立后双向对称，单边可达
即可维持全部功能。
| 新面板 / 新联邦 | ✓ | ✓ | ✓ |

- invite 串格式、`peers.url`、面板上游 URL 全部不变；
- 合并端拒绝的未知令牌一律 401（可诊断），不会误接成另一种连接。

## 备选与否决

- **路径路由**（`/fed` 给联邦、`/` 给管理）：需改 invite 串与 dial URL，
  旧对端直接破坏；而令牌路由零改动即达同等效果。否决。
- **首帧嗅探**（连接后按首帧类型归类）：引入分类延迟与协议耦合；仅可
  作为表 #4 角落场景的诊断增强（连接被归为管理后若首帧是
  `FedFrame::Hello`，明确记录「未知令牌的联邦误连」并断开）——列为
  可选后续，不作主判据。
- **协议级多路复用**（FedFrame 并入管理协议）：耦合两套协议演进与认证
  命名空间，爆炸半径大。否决。

## 实施计划

| 阶段 | 内容 | 主要位置 |
|---|---|---|
| 链路层 | 同步令牌镜像（`new`/`add_peer`/`remove_peer` 镜像 per-peer 令牌，供升级回调同步读取）+ `has_peer_token` + `accept_ws` 包装 + 常时比较 | `source/federation/echo-federation/src/link.rs` |
| 装配层 | 拆 `handle_ws`（升级后主体，独立模式行为不变）；`classify` 分类器；`serve_merged` 合并监听；启动校验（安全条件 1/2）；`run_core` 同址判定与接线（联邦 `run` 仅起连出，合并监听挂「管理面」插件生命周期） | `source/core/src/management.rs`、`source/core/src/main.rs` |
| 工具层 | `port` 显示合并态；帮助文案 | `source/core/src/port_cmd.rs` |
| 文档收敛 | federation.md 增「端口合并」节、protocol.md 一句、ops-deploy.md 云机配方；本页状态更新 | `document/*` |
| 验证 | 单测 + 集成 + 本机双核冒烟（见下） | `source/core`、`source/federation` |

生命周期语义（明确写入文档）：合并监听挂「管理面」插件——禁用管理面
= 同时关停管理通道与联邦**入站**（出站联邦不受影响，仅连出节点可继续
dial 出）。

## 测试计划

- **单元·分类表**：决策表 #1–#6 全覆盖；管理令牌/peer 令牌等值冲突拒绝。
- **单元·校验**：合并 + 空令牌 + 非回环拒绝（含错误文案断言）；回环放行；
  同址判定（trim/空串边界）。
- **单元·令牌镜像**：`add_peer`/`remove_peer`/更新后 `has_peer_token` 一致性。
- **集成（真 WS）**：合并监听下三连——① 管理客户端（带令牌）连接并完成
  命令/事件往返；② 联邦客户端（peer 令牌）完成 Hello/Welcome 并互发帧；
  ③ 未知令牌 → 标准 HTTP 401。
- **回归**：独立模式（两地址不同）全部既有测试零改动通过。
- **实机冒烟**：本机双核（A 合并、B dial A）互连 + 面板连 A + 401 探测，
  端到端验证后交付。

## 验收口径

1. 同址配置下，面板（含旧版）经合并端口全功能可用；
2. 联邦对端（含旧版 dial 入）经合并端口完成握手并互发帧；
3. 未知令牌返回标准 401（非静默断开）；
4. 独立模式行为与现状完全一致；
5. 非回环 + 空管理令牌的合并配置启动失败且信息可执行；
6. `port` 工具一眼可辨合并状态。

## 风险与未决问题

- **决策点（已拍板，2026-10）**：
  1. 安全条件 1 = **fail-closed 拒绝启动**（**显式**合并；含启动校验错误
     信息与补救命令提示）；运行时 `SaveFederationPeer` 同样拒绝冲突令牌。
  2. ~~合并判定 = 同址即合并~~ → **演进为「缺省合并」**（2026-10 用户
     反馈：`port` 清单里不应再出现独立 federation 端口）：`listen` 未配置
     即跟随管理地址；三保守场景（回环管理地址 / 空令牌且非回环 / 令牌与
     peer 冲突）自动回退独立监听；显式配置（含空串）优先。
  3. 合并监听 = 挂「管理面」插件生命周期（禁用管理面 = 联邦入站同停、
     出站不受影响；启动期检测到该组合会给出 warn）。
- **实现落点**：`echo-federation`（同步令牌镜像 `has_peer_token_sync`、
  `accept_ws_pub`、常时比较）+ core（`management.rs` 分类器/`serve_with_federation`
  /启动校验；`main.rs` 同址判定与接线；`port_cmd` 合并标记）。
- **已知边界**：地址比较为字符串精确匹配（不做 `0.0.0.0` 与 `[::]`
  等价归一）。表 #4 兼容分支（空令牌核心收到未知令牌→归为管理）保持
  旧行为；**首帧嗅探诊断已实现**（管理连接收到联邦帧 → 记录「疑似未知
  peer 令牌误连」并断开，仅作诊断不作路由判据）。
