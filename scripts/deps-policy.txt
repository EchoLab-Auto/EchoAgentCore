# echo-* 依赖白名单 —— 依赖方向的**单一真值来源**
#
# 两处门禁共读本文件，避免「CI 绿但实际越界」：
#   - `scripts/check-deps.sh`（CI 的 dependency-direction-lint job，纯 bash）
#   - `source/modules/core/tests/module_dependency_direction.rs`（cargo test）
#
# 格式：`<source/ 下相对目录> <允许的 echo-* 依赖...>`（空白分隔）
#   - 空行与 `#` 注释被忽略；
#   - 每行是**完整白名单**（不是增量）：列出的依赖之外一律违规；
#   - `[dependencies]` 与 `[dev-dependencies]` 都算。
#
# 纪律：
#   1. **新增 crate 必须登记**——两处门禁都会报「未登记」并失败（fail-closed），
#      忘登记不会静默放行；
#   2. **`echo-agent`（业务 crate）只允许出现在 `modules/core`**（组合根）；
#      `echo-agent-core` 是二进制名，不应被任何 crate 依赖；
#   3. 方向只向下：定义层 → 机制层 → 模块层 → 宿主 → 组合根。想在模块里用
#      框架能力，走服务键 / `HostCall` / trait 注入，而不是 `use echo_agent::…`。
#   4. **模块之间互不依赖**（2026-11 S12）。想共用类型 = 那个类型该下沉到
#      `echo-defs`（它是"跨边界词汇"）；想调用能力 = 走服务键。允许的例外
#      只有机制 crate：`echo-module` / `echo-module-api` / `echo-module-host`
#      / `echo-module-sdk` / `echo-module-loader`——它们是"模块怎么装"，
#      不是"某个模块"。
#
#      为什么这条要写死：2026-11 实测有 4 处模块互依赖（federation → subagent
#      / tools / workspace，tools → provider-llm），全部是"一个 trait/struct
#      长在了错的一边"。它们一直能编译、一直没人拦——于是想替换 federation
#      就必须先接受 subagent。收紧后同类问题在 `cargo build` 就红。
#
# 分层依据见 document/overview/architecture.md；Phase 3 外迁记录见
# document/design/decoupling-plan.md。
