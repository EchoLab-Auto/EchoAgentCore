# 找梗与考据的工作方法

遇到"这是什么梗/这影射什么/出处是什么/这张图哪来的"类任务时按此执行。

## 0. 图片类任务：先以图搜图，再谈理解

- **看到图先反查，不要先猜。** 视觉模型只能描述五官/构图，猜角色靠相似度必错。
- 本地可用：百度识图（`https://graph.baidu.com/pcpage/index?tpl_from=pc`，Playwright 上传 file input，跳转到 `graph.baidu.com/s?...` 后读 body，能拿到"图中可能是 X"、图片来源标题、相似图片）。
- 同一张图多截几个区域各搜一次（整图 / 人脸特写），命中率不同。
- 反查结果的**关键在文字**：来源视频标题、关联帖子标题（如"为啥 peter 换脸图这么多"）比相似图更有信息量。
- 视觉模型只用于：确认候选、比对细节。用法是**给定候选列表让它选**（"候选 A/B/C/D，只回答一个字母"），而不是开放地"你觉得像谁"——开放提问它会给你看似合理但错的答案。
- 环境限制：saucenao / ascii2d / iqdb / Google Lens / Yandex 在本机网络不通（返回 000/超时），不要在这上面反复试。Bing 的 visualsearch 也会超时。

## 1. 穷尽显式线索，先查再推理

- 把画面/文本里所有专有名词、场景元素（招牌、地名、人名、日期、物品、画风签名）逐个列出当查询词。
- 每个元素先单独搜一遍有没有对应实时事件，再开始理解剧情。
- 任何"看似只是背景"的元素都可能是梗的锚点，禁止默认其为无意义装饰。

## 2. 语言跟随事件属地

- 中文搜不到不等于不存在。事件发生在哪，就用哪的本土搜索和语言：
  - 韩网 → Naver（search.naver.com，Playwright 渲染可读）
  - 日网 → Yahoo 日本 / Google 日本
  - 国际 → 英文关键词
- 不要用中文去硬搜国际事件，百度百科式命中等于没搜。

## 3. 分层验证映射

- 梗的结构通常是"现实事件 → 作品角色/场景"的映射，或"角色 A 的脸 → 角色 B 的构图"这类换头式。
- 找到候选后必须能对上：谁对应谁、哪个细节对应哪个细节。
- 对不上就是还没找到真正的事件/角色，继续找，不要强行解释。
- 换脸/恶搞类：先定构图原型（原梗是谁的姿势），再定叠加元素（谁的脸），两者都要有独立证据。

## 4. 区分内容分析和语境分析

- 内容（台词、画面、剧情）：靠下载、ASR、视觉模型等工具分析。
- 语境（为什么是这个题材、为什么现在发、梗的传播路径）：只能靠外部信息检索。
- 顺序：先语境后内容。语境没搞清时做内容分析是浪费时间。

## 5. 失败时扩大查询面而非加深分析

- 一个方向搜不到，别在原方向加深度（换 ASR 模型、换视觉模型之类）。
- 加宽度：换语言、换平台、换同义词、换视角（从事件侧反推作品侧）。
- 同一关键词撞两次百科/无关结果就换语种，不要第三次。
- 换工具而不是换措辞：文字搜不动就上以图搜图，图搜不动就去垂直站（B站/贴吧/NGA/萌百）。

## 常用检索通道（本机实测可用）

| 目的 | 通道 | 备注 |
|---|---|---|
| 中文网页/时事 | 百度（Playwright 渲染） | `curl` 直连常被拦，用浏览器 |
| 韩网 | search.naver.com | 必须 Playwright + 移动 UA |
| 图片反查 | graph.baidu.com | 见 §0 |
| 二次元资料 | 萌娘百科 / B站搜索 API | B站搜索 API 限流严重，`order=pubdate` 需间隔 |
| 视频内容 | B站 playurl（`platform=html5&qn=16`）+ ffmpeg + faster-whisper | 见下 |

## 内容分析流水线（已跑通）

1. 短链 `b23.tv` → `curl -sIL` 取 location 拿 BV 号
2. `x/web-interface/view?bvid=` 拿 title/owner/cid/stat
3. `x/player/playurl?...&platform=html5&qn=16` 拿 mp4 直链（需 Referer）
4. 宿主机无 ffmpeg → `docker cp` 进 NapCat 容器转音频 → `docker cp` 回来
5. `faster-whisper` medium/int8/8 线程；中文长音频约 20 倍实时耗时，超时要放后台跑并轮询输出文件
6. 抽帧给视觉模型：一次多图（≤7 张，缩到 800px）合并提问比逐张问省事

## 反模式（教训积累）

- **凭视觉相似猜角色**：把 Peter Griffin 猜成章鱼哥，错得离谱。图必须反查。
- **开放提问视觉模型**："这像谁"会得到自信的错误答案；要给候选让它选。
- 过早收敛：搜两次没结果就换方向，把核心线索当背景板。
- 关键词太死：单一语言直搜，撞上百科词条还以为搜过了。
- 工具用偏：花大力气分析画面内容，忽略真正的线索在外部事件里。
- 映射理解浅一层：角色不只是参演，可能是组织者——要追到功能位。
- 搜不到就断言"不存在"：先怀疑通道不对（语言/平台/被墙），再怀疑事实。
