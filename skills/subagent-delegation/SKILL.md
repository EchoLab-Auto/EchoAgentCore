# 子任务委派（subagent）

## 何时委派

把满足以下特征的子任务交给 `spawn_subagent`：

- 探索性检索/批量分析：会产生大量中间工具调用，但你只需要结论
- 隔离试错：不想让中间过程污染当前对话上下文
- 可并行推进的独立事项：委派后你可以继续当前回复

不要委派：需要当前对话上下文才能回答的问题（子 agent 看不到）、简单一步
就能完成的操作、需要把结果直接发给 QQ 用户的任务（子 agent 不能投递外部
平台，结论由你转述）。

## 实现类任务的并行拆分

探索/检索类任务天然适合并行委派（只读、无冲突）。实现/编码类任务也能并行，
但必须按**接口边界**拆：

1. 先由你冻结共享接口（数据类型、组件 props、模块契约），写进各子任务的
   task 里——接口不定就拆，子 agent 会各自发明不兼容的约定
2. 只拆**文件零交集**的实现单元（如两个独立组件文件）；多个子任务改同一个
   文件必然冲突，禁止并行
3. 集成步骤（把产物接进宿主文件、测试适配、构建部署）天然串行，由你完成，
   不要委派——子 agent 的上下文同步成本高于省下的时间
4. 委派门槛：子任务在隔离上下文里预计要跑 2 分钟以上才值得；几十行的小
   改动，启动与回报开销大于收益

## 硬规则

- task 必须自含全部背景与目标：子 agent 在全新隔离上下文里执行，看不到
  当前对话、看不到你的系统提示词之外的信息
- 单层委派：子 agent 没有 spawn_subagent，不能再向下委派
- 异步回报：spawn 立即返回子任务 id；结论会以 <subagent_event> 事件在稍后
  送达（作为新的输入事件）。不要在同一轮里等待或重复委派同一任务
- 结果会截断：子任务结论超长时只保留前 8K 字符；要求子任务"只回结论"
