# 子任务委派与并行化

## 0. 开工前：先扫"可委派块"（硬性习惯）

收到非平凡任务后、第一次动手前，花 30 秒对照下表扫描；命中任一即列入
委派候选，并写进执行计划（哪怕最后决定不委派，也要在计划里留一行理由）。

| 信号 | 动作 | 实测依据（2026-10-19 审计：最近 3 天 / 8664 次调用 / 306 个片段） |
| --- | --- | --- |
| 调查 / 分析 / 审计 / 排障类，预计探查命令 > 5 条 | 探查包整体委派，按线索拆 1–3 个子代理 | 此类片段中位 16 步、p90 74 步，几乎全长在"读全仓"上 |
| **预计本片段工具调用 > 30 次**（阈值 2026-10-19 从 40 下调） | **至少委派 1 个子代理**，把"读全仓"的中间过程移出主上下文 | ≥50 步的 52 个片段吃掉 **55.5%** 的全部调用；30–49 步还有 43 个 |
| **预计本片段工具调用 ≥ 90 次** | **强制至少 1 次委派**（不许"我能扛"） | ≥90 步的 17 个长片段里 **16 个（94%）零委派**，是当前最大浪费 |
| 跨仓库 / 跨模块改动，且文件零交集 | 按仓库 / 单元并行委派实现（各给 worktree 或文件白名单） | 10-15 worktree 三连 3/3 成功，回报 2.1–2.3K 字符 |
| 文档同步、真实数据离线验证、回归脚本、远程环境安装 | 与主线**并行**委派，主线继续集成 | 10-16 12:55 委派远程 a100-40g 完成 isaaclab 安装，主线不受阻 |
| 单项子任务预计 > 8 分钟（大规模构建 / 全仓审查 / 长验证） | 先按"单仓库 / 单模块"再切一刀；仍超则**显式传 `timeout_secs`** | 4 次超时（900s×2、600s×2）全是跨仓库 / 全仓审查；同批次单仓库评审则成功 |
| Playwright / 浏览器 / 网络实测 / 大批量肉眼比对 | 委派，只要结论与数字 | 此类中间输出全是数值噪声，主线程只需结论 |

**当前覆盖现状（必须改）**：38 次 `spawn_subagent` / 306 个片段 = **覆盖 6.5%**；
按片段规模的覆盖率是 1–9 步 1.7%、10–29 步 8.5%、30–49 步 9.3%、50–89 步
14.3%、**≥90 步 5.9%**——越大越不委派，完全反了。

委派判断口径：**在隔离上下文里预计跑 ≥2 分钟，且产物可独立验收**。不满足
就别委派——启动与回报开销大于收益。

不要委派：需要当前对话上下文才能回答的问题（子 agent 看不到）、简单一步就
能完成的操作、需要把结果直接发给 QQ 用户的任务（子 agent 不能投递外部平台，
结论由你转述）、两个子任务会改同一个文件 / 同一接口的。

## 1. 并行的三种手段（按此优先级选择）

1. **同轮打包多条独立工具调用** —— 最便宜的并行：一次响应里发多个
   tool_call（框架会逐个 `await` 串行执行，但**只消耗一次模型往返**）。
   实测：平均每轮只有 **1.07 条调用**、单调用轮占 **95.3%**，而跨轮间隔
   中位 **2.44s**、p90 14.4s。看到"要看 3 个文件 / 3 个目录"，就**一次发 3 条**。
2. **单条 bash 内后台批处理** —— 同一个响应里塞不下（或需要等待组合）时，
   I/O 型探测（curl/ss/journalctl/网络测试等）互相独立时并发跑完：
   ```bash
   cmd1 >/tmp/p1.log 2>&1 & p1=$!
   cmd2 >/tmp/p2.log 2>&1 & p2=$!
   wait $p1 $p2
   cat /tmp/p1.log /tmp/p2.log
   ```
3. **spawn_subagent** —— 唯一跨上下文的真并行：立即返回子任务 id，后台执行，
   完成后以 `<subagent_event>` 回报（新一轮输入）。需要在**隔离上下文**里跑
   大量探查、且只想要结论时用它；只是本机几条快探测用第 1、2 条。

## 2. 委派 task 模板（自含 + 只要结论）

子 agent 在全新隔离上下文里执行：看不到当前对话、你的推理、此前的工具输出。
task 必须自含全部背景。按模板写：

```text
背景：<项目/仓库绝对路径；目标与当前状态；相关文件或上一步结论>
要做：<精确步骤；能给命令就给命令；可自由探索的范围边界>
约束：只读 / 只改列出的文件（建议写白名单）；不要动 git；不要反问（没人能
      答），拿不准就按合理假设继续并在结论里注明
产出：结论 + 关键数字 + 文件:行号；≤800 字；不要贴大段原始输出
```

写 task 时的三条硬规则：

- **一个子任务 = 一个产出物**。要 4 份文档/4 个仓库结论，就发 4 个子任务并
  在 task 里写清各自的确切产出路径；实测"按产出物切分"的批次 4/4 成功
  （03a/03b/01a/01b 四份互不重叠的文档），而"一个包打天下"的批次连续 4 次
  524 失败。
- **产出物必须唯一**（路径写死），否则两个子代理会写出两份同题文档。
- **结论超长会被截断（保留前 8K 字符）**——要求"只回结论"，长清单用文件
  落盘并回路径。
- 单层委派：子 agent 没有 `spawn_subagent`，不能再向下拆分；所以**切分在你
  这一层做完**。
- 超时：默认 600s（可传 30–3600s）。预计更久（大规模构建/长验证/远程装环境）
  显式传 `timeout_secs`；预计 >8 分钟又必须一次做完时，宁可按范围再切一刀。

模型与节点（细则见 `model-profiles` 技能）：

- 不传 `profile` = 继承主模型（通常就该如此）；UI 前端图形 / 视觉闭环作业传
  `profile: "kimi"`；**不确定就先 `list_api_profiles` 看可用清单**——名字不存在
  或缺 key 会 fail-closed 立即失败（不会静默回退）。
- 需要远程机器（装环境、跑 GPU、访问另一台机）时传 `node`（如
  `node: "A100-40g"`，来源：工具列表 `<peer>__<tool>` 前缀名）。填错/离线同样
  立即失败，按错误信息纠正后重发。

## 3. 实现类任务的并行拆分

按**接口边界**拆，且只拆文件零交集的单元：

1. 先由你冻结共享接口（数据类型、组件 props、模块契约），写进各子任务
   task——接口不定就拆，子 agent 会各自发明不兼容的约定
2. 集成步骤（产物接进宿主文件、测试适配、构建部署、git 提交）天然串行，
   由你完成，不要委派
3. 多子任务改同一文件必然冲突，禁止并行；能开 git worktree 就各给一个
   worktree，并在 task 里写明"只能改这些文件"

## 4. 失败与重试（硬停止条件）

基础设施类失败（`子任务执行失败：HTTP 请求失败…` / `API 返回错误: HTTP 4xx/5xx` /
`子任务超时（Ns）`）与"任务本身写错"要区别对待：

| 看到 | 动作 |
| --- | --- |
| 同一 task 在同一 `profile`/`node` 上第 1 次基础设施失败 | 允许重发 1 次（可微调 task） |
| **第 2 次仍失败** | **换策略，禁止第 3 次原样重发**：①换 `profile`（先 `list_api_profiles`）②换 `node` ③把任务**再切小**（按产出物拆成 2–4 份）④改由自己做 |
| 超时（`子任务超时`） | 一律先缩范围再重发：把"全仓/跨仓库"降为"单仓库/单模块"，或按产出物拆分；需要保原范围则显式加大 `timeout_secs` |
| 子任务回报"文档已写好"但内容重复 | 说明产出物路径没写唯一——下次在 task 里写死路径 |

实测代价：13 次失败全部是基础设施类（524 ×5、网络层 ×4、超时 ×4），其中
**8 次是同一 task 的重发**；两个失败簇光 `uu-api` 就烧掉 **6.7M + 7.9M prompt
tokens**、约 50 分钟无产出等待。

## 5. 等回报期间不空转

- 委派是异步的：**不要反复查询或重复委派同一任务**；把"等待"用来推进
  非重叠工作（写文档、准备测试、处理部署、检查环境）。实测 14 个多子任务
  父分支里 13 个是这样做的，继续照做。
- 回报到达后：先抽查关键数字/事实（子 agent 会出错），再向用户转述；多个
  子任务结论冲突时，自己动手复核分歧点。
- 回报到达 → 你的下一个动作间隔实测中位 10 秒（属正常推理延迟），无需怀疑
  阻塞；但若回报后已无意义（任务被取消/变向），明确说明而不是硬凑进回复。
- 子任务结果作为新的输入事件消耗，不要为"已作废的结果"补做工作。

## 6. 汇报口径

对用户只报"做了什么 + 结果 + 证据"（如"委派 2 个子代理并行调查，合计
节省约 X 分钟"），不复述子任务内部过程。

## 7. 发车前自检（5 问，任一为"否"就别发）

1. **自含？** 把 task 单独给一个陌生人看，他能不追问就开工吗（路径、现状、
   命令都在里面）？
2. **产出唯一？** 有确切的产出物（文件路径 / 结论清单）且与其它子任务不重叠？
3. **配置可用？** 要用 `profile`/`node` 的话，名字已从 `list_api_profiles` /
   工具列表核对过？
4. **时间够？** 预计耗时有数，超 8 分钟已传 `timeout_secs` 或已再切一刀？
5. **只要结论？** task 里写了"只回结论 + 关键数字，≤800 字，不贴原始输出"？

## 8. 执行中触发式复检（新增，2026-10-19）

步数不是一次判断的，要在执行中复查：

- **第 30 步**：还没委派过 → 立刻问"剩下的哪一块可以打包给子代理"（哪怕只是
  把"读 5 个文件 + 跑 3 个回归"整包丢出去）。
- **第 50 步**：仍未委派 → 必须委派一块，或明确写下"不委派的理由"
  （例如全部步骤都依赖当前上下文）。
- **第 90 步**：硬性要求本片段已有 ≥1 次委派；没有就先停下来委派，再继续。
