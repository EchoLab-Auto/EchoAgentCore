# ProDoc 文档格式规范

ProDoc 是一种基于 Markdown 的文档组织约定，定义了如何将一组 Markdown 文件组织成可供 ProDoc 渲染器识别和渲染的文档结构。

> 当前模型为**文档图**（DocGraph）：目录即图，文件即框，连线表达导航。旧的「文档树」模型（`order` 排序、`index.md` 目录节点）及其 `edit` 命令已移除。

## 零、本规范的边界（rule0）

本规范**只定义文档的组织与格式约定**——即「写什么」：文件要求、框架参数区、框的属性、连线声明、文档分组、分层布局、prodoc-flow 流程图语法。这些内容决定一组 Markdown 文件能否被 ProDoc 渲染器识别与渲染。

以下内容**不属于本规范**（属于渲染器的实现与交互行为，即「怎么呈现 / 怎么操作」）：

- 画布与正文的交互操作（平移 / 缩放 / 编辑模式 / 按钮与快捷键等）
- 查看器的行为细节（热更新机制、地址栏同步、暂存与保存流程等）
- 渲染器的内部实现规则

这些内容的权威定义见 echo-prodoc 仓库（github.com/EchoLab-Auto/DocRenderer）的文档：[ProDoc 规则定义](https://github.com/EchoLab-Auto/DocRenderer/blob/main/document/develop/prodoc-rule/prodoc.md)与[交互设计](https://github.com/EchoLab-Auto/DocRenderer/blob/main/document/develop/interaction-design/interaction-design.md)。本规范仅在「渲染器会改变文件内容」时提及该事实（如可视化编辑把坐标 / 标签写回参数区），不描述其操作方式。

## 一、文件格式

所有 ProDoc 文档必须是 **`.md` 扩展名** 的 Markdown 文件，使用 UTF-8 编码。

## 二、核心模型：文档图

ProDoc 把一个文档目录（文档群）视为**一张图**，而非目录树：

- **每个 `.md` 文件 = 图上的一个框**（box），目录层级只影响路径，不构成父子关系
- 框的属性（标识、标题、位置、尺寸）由文件最前方的**框架参数区**声明
- 框间用 `link` 参数声明的有向连线表达导航关系，连线结构决定框的**层级深度**
- 相同 `group` 名的框被围入一个圆角矩形**分组区域**（见 §4.4）
- 正文的 **H2 标题**自动提取为**文档内分块**，悬停框时展开为可跳转面板
- 文档群被整体渲染为一张可交互画布，点框即跳转到该文档的正文

## 三、框架参数区

### 3.1 语法

每个 `.md` 文件的**最前方**（文件第 0 字节起）是由两个 `---` 行夹住的参数区：

```
---
id: getting-started
title: 快速开始
x: 40
y: 64
---

# 正文从这里开始……
```

- 第一行必须是单独的 `---`；之后是若干 `key: value` 参数行；以一行单独的 `---` 结束
- 结束行之后的所有内容即**正文**

### 3.2 剥离规则（渲染不可见）

参数区**仅供框架消费**，正文渲染时完全剥离；读者在查看器中看到的一切（正文、目录、链接）均基于剥离后的正文。

### 3.3 值类型

| 类型 | 示例 | 说明 |
|------|------|------|
| 整数 | `x: 40` | `^-?\d+$` |
| 浮点数 | `scale: 1.5` | `^-?\d*\.\d+$` |
| 布尔值 | `draft: true` | `true` / `false` |
| 内联列表 | `link: [guide, api]` | 方括号包裹、逗号分隔；成员继续按本表规则解析；可跨行书写（`[` 起、`]` 收，成员可各占一行） |
| 引号字符串 | `title: "快速开始"` | 双引号或单引号包裹，取内部内容 |
| 裸字符串 | `author: 张三` | 以上都不匹配时，原样作为字符串 |

### 3.4 容错

- 文件**不以 `---` 开头**：视为无参数区，整个文件按普通正文处理
- 文件以 `---` 开头但**找不到闭合的第二个 `---`**：视为无参数区，整个文件（含开头的 `---`）按正文处理——宁可显示原文，也不吞掉内容
- 参数区内**无法识别的行**：跳过，不中断解析

## 四、框的属性

### 4.1 框架保留字段

| 字段 | 类型 | 必填 | 缺省行为 |
|------|------|------|----------|
| `id` | `string` | 否 | 取文件相对路径去掉 `.md`，如 `guide/getting-started` |
| `title` | `string` | 否 | 取正文第一个 H1；再缺省取 `id` |
| `x` | `number` | 否 | 缺省时按连线层级分层自动布局（见 §六） |
| `y` | `number` | 否 | 同上 |
| `w` | `number` | 否 | `220` |
| `h` | `number` | 否 | `96` |
| `link` | `string[]` | 否 | 当前文档指向其他文档的连线（见 §五） |
| `group` | `string` | 否 | 所属分组名，同组框被围入圆角矩形区域（见 §4.4） |

`title` 缺省回退链：`参数区 title → 正文第一个 H1 → id`。

### 4.2 自定义字段

参数区中除保留字段外的任意字段都会被解析并存入框的 `attrs` 对象，供框架或上层工具扩展使用，不影响渲染。

### 4.3 文档内分块

正文的 **H2 标题**（`## 分块名`）会被自动提取为框的 `blocks`：

- 仅当文档包含 **2 个及以上 H2** 时提取；代码围栏内的 `##` 不视为标题
- 悬停（或键盘聚焦）框时从框底弹出分块面板；贴近画布底边的框向上弹出
- 面板最多展示 6 个条目，超出折叠为 `+N 更多分块…`
- 点击面板条目打开正文并**滚动到对应标题**

### 4.4 文档分组

`group` 声明当前文档所属的分组，相同组名的框在画布上被围入一个**圆角矩形区域**（虚线描边 + 骑跨顶边的组名标签）：

```yaml
---
id: guide
group: 使用指南
---
```

- 一个文档最多属于一个组；声明多个（列表）时仅取第一个并记录警告；不支持嵌套
- 缺省时区域 = 成员包围盒 + 内边距（左右/下 24px，顶部 34px 留标签位），随成员移动自动重算
- 任一成员可在条目上**显式声明区域几何**：`group: "名称 @ x, y, w, h"`；显式区域不随成员移动；多成员声明不一致时取路径字典序首个并告警
- 查看器中可可视化调整分组（整组移动 / 调整区域长宽），结果写回各成员坐标 / 几何持有者的 `group` 条目，无需手写
- 分组区域可**折叠成一个超节点**：折叠后组内成员不再逐个绘制，组与组之间的连线重定向到这个超节点上。文档规模变大（> 60 篇）时这是保持画布可读的主要手段——全展开时画布上只有密集的框和线，没有可读结构
- `group` 属于框架保留字段，不进入 `attrs`

## 五、连线关系（link）

`link` 直接声明当前文档指向其他文档的有向连线，方向为「当前文档 → 目标文档」：

```yaml
---
id: project
link: [guide, api]
---
```

### 5.1 标签

条目可携带标签，`|` 之后的文字显示在连线中点（查看器中可可视化编辑并写回条目，无需手写）：

```yaml
link: ["guide | 使用指南", api]
```

### 5.2 连接边

条目可追加第三段指定**连接边**——`源边>目标边`，`t/r/b/l` 分别表示上/右/下/左，`_` 表示该端保持自动：

```yaml
link: ["guide | 使用指南 | b>l", "api | r>t", "note | t>_"]
```

缺省时按两框主导方向自动选边；标签与连接边按模式识别、互不占位（`user | r>l` 即无标签仅指定边）。查看器中可可视化调整连接边并写回，无需手写。

### 5.3 解析与容错

- 引用优先按文档 `id` 解析，也可写相对文档根的路径（`.md` 后缀可省略）
- 重复声明同一连线时自动去重
- 引用不存在的文档或连线自身时记录警告，不生成连线，也不中断渲染
- `link` 属于框架保留字段，不进入 `attrs`

### 5.4 连线渲染

连线渲染为**贝塞尔曲线箭头**：端点取所连边的**边缘中点**，控制点沿两端边的外法线布置——曲线在两端始终与边线法线相切；标签文字显示在连线中点。

分层图中，目标位于**下一层或更深**的连线一律「底出顶进」（从源框底边出发、进入目标框顶边）。同层连线（两框 y 区间重叠）仍按主导方向自动选左右边。这条规则保证边不会横穿整排兄弟框。

### 5.5 `link` 的书写顺序决定层内左右顺序

同属一个父的兄弟文档，在画布上**从左到右的次序 = `link` 数组里的书写顺序**：

```yaml
# project.md
link: ["user | 开始使用", "develop | 开发指南", "reference | 参考手册"]
```

```
              project
     ┌───────────┼───────────┐
    user      develop    reference
    (左)        (中)        (右)
```

- 顺序来自**参数区内容**，与文件的加载顺序、目录遍历顺序无关——同一份文档群在任何机器上都得到同一张图
- 它只决定**兄弟之间的相对次序**，不决定绝对位置（哪个父在左、哪个父在右，由它自己的父决定）
- 想让某组文档从左到右按「使用 → 开发 → 参考」排，就在父文档的 `link` 里按该顺序书写，无需手写坐标

## 六、层级深度与分层自动布局

每个框根据 `link` 连线结构计算**层级深度**：根框（无入边）深度为 0，其余框深度 = 父框最大深度 + 1。计算先对连线做**强连通分量**归约（Tarjan），环上成员视作同一节点，因此**环不会导致无限深度**，环上的框排在同一层。

缺省 `x` / `y` 的框按深度**分层自动排布**，共四步：

**1. 层内初始顺序** —— 按「父的秩 → 在父 `link` 里的下标 → id」排序。父的秩按层逐层编号，因此**兄弟严格按 `link` 书写顺序排列**（见 §5.5），不同父的子树在层内各自连续。这个键只依赖参数区内容，所以结果与文件遍历顺序无关。

**2. 减少交叉** —— 重心排序（每个框趋向邻居位置的平均）+ 相邻交换多轮迭代。交换的采纳条件是「交叉数下降」，或「交叉数持平但连线在层内的跨度总和更小」。

**3. 横坐标** —— **保序最小二乘**求解。目标函数是两项加权和：

- **父节点正对子节点群中部**（权重最高，这是产品需求）
- 连线尽量短直

约束是同层保序且相邻间距不小于 `gapX`（默认 64）。用投影梯度 + 精确保序投影求解，目标单调下降，**有确定的收敛点、不会振荡**。显式给出 `x` 的框钉死不动，其它框的求解会绕开它。

**4. 纵向** —— 每层一条层带，框在带内垂直居中，层间距 72；整体平移到 padding（默认 48）。

其它行为：

- 跨多层的长边会插入**虚拟节点**参与排序与横坐标求解，其位置即连线的拐点，因此长边不会横穿中间层的框
- 显式给出坐标的框不受影响；只缺一个坐标轴时仅补写缺失轴
- **默认不修改源文件**。自动坐标只在内存中计算，需要固定时用 `view --persist-layout` 写回参数区

### 6.1 超宽层换行（默认关闭）

`wrapThreshold` 控制单层最多排多少列，默认 `Infinity`（永不换行）。

层数少、节点多的图不换行会变成细长横带（实例：一棵 259 节点的三层树不换行时是 61280 × 600，长宽比 102）。把 `wrapThreshold` 设成 30~50 可把宽度压回可读比例。

**但它有明确代价，不是免费的改进：**

- 换行后「父在第 2 行、子在第 5 行」的边必须穿过中间行的框，实测会让 60% 以上的边穿框
- 跨行的父子不再居中对齐（父只能对齐到其中一行）

**所以默认关闭。** 文档规模变大时正确的做法是**折叠分组**（见 §4.4）与分层拆入口，而不是靠换行把大图硬塞进一个视口。

## 七、流程图语法（prodoc-flow）

ProDoc 支持用 ` ```prodoc-flow ` 代码块在文档中定义**流程图**。渲染时该代码块呈现为**可交互的流程画布**（拖拽平移、Ctrl+滚轮缩放、一键适配），流程中的节点可以关联文档，点击节点即跳转。

### 7.1 方向声明

第一个有效行必须是方向声明：

```
graph LR
```

| 方向 | 含义 |
|------|------|
| `LR` | 从左到右（默认） |
| `RL` | 从右到左 |
| `TB` | 从上到下 |
| `BT` | 从下到上 |

缺少方向声明时按 `LR` 处理并记录一条解析警告。

### 7.2 节点

| 语法 | 形状 |
|------|------|
| `A[文本]` | 矩形 |
| `A[/文本/]` | 圆角矩形 |
| `A(文本)` | 体育场形 |
| `A{文本}` | 菱形 |
| `A` | 裸 id 引用（自动登记为矩形，显示文本为 id） |

- 节点 id 为裸标识符（字母/数字/下划线/连字符，字母开头），文本可含空格与中文
- 同一 id 的完整声明后出现时会**合并升级**先前的裸引用（后者优先）
- 独立一行的 `A[文本]` 是节点声明；节点也可在边行中内联声明

### 7.3 边与标签

```
A --> B          %% 基本边
A -->|是| B      %% 带标签的边
A --> B --> C    %% 链式（等价于 A --> B、B --> C）
```

完全相同的边（起点 + 终点 + 标签）重复声明时只保留一条。

### 7.4 文档链接

节点文本中以竖线附加文档路径，即把节点变为**可点击的文档链接**：

```
A[首页|/index.md] --> B[用户中心|/api/user.md]
```

- 路径必须以 `/`、`./` 或 `../` 开头并以 `.md` 结尾，相对文档根目录
- 带链接的节点渲染为主色描边 + ↗ 图标，点击（或 Enter/Space）在查看器内跳转

### 7.5 注释

`%%` 之后的内容为注释（可整行或位于行尾）。

### 7.6 容错规则

- 无法识别的行不会中断解析，而是被跳过并记录到解析警告中
- 整个代码块没有任何有效节点时，按普通代码块原样显示源码
- 建议单张流程图节点数控制在 30 个以内，以保证自动布局的可读性

### 7.7 手动排版（`@ x, y`）

节点声明行尾可附加画布坐标（节点左上角，px），显式坐标的节点不再参与自动排布：

```
graph LR
  A[开始] @ 48, 96
  B[处理] --> C[结束]   %% 未标注的节点照常自动布局
```

- 坐标为最终视觉坐标（与方向镜像无关）；只给部分节点标注时，其余节点自动分层排布
- 边链行尾的标注绑定到**链尾节点**：`A --> B @ 40, 64` 设定的是 B
- 查看器中拖拽节点调整排版时，坐标以 `@ x, y` 形式自动写回该代码块（仅出现在边链中的节点会在块尾追加一行坐标声明），无需手写

## 八、完整示例

```
my-docs/
├── index.md
├── guide.md
└── note.md
```

`index.md`：

```markdown
---
id: home
title: 首页
x: 40
y: 40
link: ["guide | 指南"]
---

# 首页

这是文档群的入口。[前往指南](./guide.md)
```

`guide.md`（含分块，悬停框可展开面板）：

````markdown
---
id: guide
title: 使用指南
x: 400
y: 40
---

# 使用指南

## 安装

## 配置

```prodoc-flow
graph LR
  Home[首页|/index.md] --> Guide[使用指南|/guide.md]
```
````

`note.md`（无框架参数区，分层自动布局）：

```markdown
# 无参数区文档

这个文件没有参数区，会自动获得一个框，标题取自 H1。
```

## 九、内容规范建议

1. **标题层级**：每个文件以单一 H1（`#`）开头作为页面标题，正文从 H2（`##`）开始——H2 同时是画布分块面板的条目，命名应简洁可导航
2. **参数区最小化**：`id`/`title` 多数情况可省略（回退链足够好用）；`x`/`y` 交给自动布局，不必手填（画布拖拽也会写回，但那是「定稿」而非「起步」该做的事）
3. **连线即导航，且只是导航**：`link` 只表达「读完这篇该读那篇」的阅读路径。想表达「这两篇内容相关」，用**正文里的相对链接**——正文链接不产生边。判断标准：删掉这条边读者会迷路吗？不会就别连
4. **每篇至多一个父**：被多个父指向的文档只有一个位置，布局只能折中，它的父节点会明显偏离子群中部。`check` **不检查多父**，只能靠 `grep` 数入度
5. **分组必须连通**：分组区域的几何 = 成员外接矩形 + 内边距。若同组两个成员被排在不同层，组框会把中间所有文档都框进去，不同组之间互相重叠。给每组加一个**组入口文档**（由根指向它，组员从它分出去），组框就只包住自己那片
6. **文件名**：使用小写字母 + 连字符命名（如 `getting-started.md`）
7. **相对链接**：使用相对路径链接到同文档群内的其他 `.md` 文件，查看器内可继续跳转
8. **代码块**：始终为代码块指定语言标识
9. **流程图**：单张图节点数 < 30；优先用文档链接把流程图变成可钻取的导航地图
